## Quirks

- `typer`: an app with a single command collapses into that command; `simagent` defines an
  `@app.callback()` so subcommands always work.
- On Windows, `Path.write_text` writes CRLF. Scripts that generate committed files write with
  `newline="\n"` so `ruff format --check` and staleness tests behave the same on Linux and Windows.

## Material data (Phase 1.1)

- `src/photonsim/data/materials.json` is generated by `scripts/build_materials.py` from NIST
  SRD 126 (Hubbell & Seltzer, X-ray mass attenuation and energy-absorption coefficients),
  for water, polyethylene, ordinary concrete, aluminium, iron and lead, 0.1–10 MeV (18 points
  each, no absorption edges in that range). Densities come from the same database (tables 1–2).
- NIST blocks Python's default `urllib` User-Agent (HTTP 403); the script sends a generic one.
- **Mapping to the simplified model (R-SIM-2):** `mu_total = rho·(mu/rho)`, `mu_abs = rho·(mu_en/rho)`.
  The model absorbs a photon with probability `mu_abs/mu_total` at each interaction and otherwise
  scatters it isotropically with no energy loss. Using the energy-absorption coefficient as the
  absorption probability is an energy-weighted approximation (the fraction of interaction energy
  deposited locally), not a physical event probability. It keeps narrow-beam attenuation exact
  (`mu_total`) while giving a plausible absorbed/scattered split. Transmission includes scattered
  photons, so it is above `exp(-mu_total·x)` (a crude build-up). Documented in the API reference.

## Sandbox (Phase 2)

- **Base image and pins:** `python:3.12.16-slim-bookworm` (tag checked on Docker Hub). The full
  wheel set in `sandbox/requirements.txt` was resolved for cp312/manylinux x86_64 with
  `pip install --dry-run --report --platform … --only-binary=:all:` and is installed with
  `--no-deps` + `pip check`. Version bumps: re-run that resolution, don't hand-edit one pin.
- **Getting `result.json` out:** R-SBX-3 needs a size-limited writable `/out` *and* `--rm`, so
  `/out` is a tmpfs that disappears with the container; `docker cp` after exit is impossible.
  `sandbox/launch.py` (in the image, standard library only) runs the script as a child process,
  then prints `result.json` after a marker line containing a random per-run nonce. The host takes
  the last marker. A script that forges a marker can only fake its own result, which it could do
  with `submit()` anyway, so this adds no new capability. Raw stdout is kept up to ~1.25 MB (tail)
  so a maximal 1 MB result survives, then the visible stdout is capped to 20 000 chars (R-SBX-6).
- **Timeouts:** `subprocess` timeouts only kill the `docker` CLI, not the container, so the
  runner names each container (`simagent-<random>`) and runs `docker kill` on timeout.
- Extra hardening beyond R-SBX-3: `--pull never` (a missing image fails fast instead of pulling),
  `--ipc none`, `--ulimit nofile=256:256`, `noexec,nosuid,nodev` on both tmpfs mounts, swap
  disabled (`--memory-swap` = `--memory`), `python -I -B` (isolated mode).
- `docker` CLI on Windows: Docker Desktop must be able to bind-mount the temp dir
  (`%LOCALAPPDATA%\Temp`, under `C:\Users`, shared by default with the WSL2 backend).
- `SIMAGENT_REQUIRE_DOCKER=1` makes pytest fail (exit 4) instead of skipping Docker tests; CI sets it.
- The policy also blocks numpy's file/native helpers (`np.load`, `np.save*`, `loadtxt`,
  `fromfile`, `memmap`, `ctypeslib`, `f2py`, …), `vars/globals/locals`, `input`, `help`,
  `memoryview`, and format strings that reach dunder attributes. `__name__` stays allowed
  (`if __name__ == "__main__":`, `type(x).__name__`).
- `LocalRunner` passes only a minimal environment (no host variables, so no API keys), plus
  `SYSTEMROOT`/`WINDIR`/`TEMP`/`TMP` on Windows, which Python needs to start.

## LLM layer (Phase 3, 2026-11-07)

- Versions: langchain-ollama 1.1.0 (ollama 0.6.3), langchain-groq 1.1.3, langchain-openai 1.7.4,
  langchain-core 1.7.6; Ollama server 0.40.15. Local model tag: `qwen2.5-coder:3b`.
- `ChatOllama` fields used: `model`, `base_url`, `num_ctx`, `temperature`, `seed`. Streaming puts
  token counts in `usage_metadata` and Ollama's timings (`eval_count`, `eval_duration`,
  `prompt_eval_*`, `load_duration`, ns) in `response_metadata` of the final chunk.
- `ChatGroq` has no `stream_usage` field; it reads usage from the `x_groq` field of streamed
  chunks. `ChatOpenAI` needs `stream_usage=True` to report tokens while streaming.
- In langchain-core 1.x `AIMessageChunk.text` is a property (it was a method in 0.3).
- Measured on the RTX 3050 4 GB: `qwen2.5-coder:3b` sits fully in VRAM (2.0 GB at
  num_ctx 4096) and generates ≈58–65 tok/s warm. The very first call after pulling took 85 s
  (39 s load + slow first prompt eval), and changing `num_ctx` forces a reload (≈7 s TTFT).
  Benchmarks should do a warm-up call per model before timing.
- First manual end-to-end check (generate prompt → qwen2.5-coder:3b → policy → Docker): one
  well-formed code block, 1460 input / 140 output tokens, TTFT 2.9 s, 65 tok/s; the script failed
  with `NameError: simagent_io` (missing import), a realistic case for the repair loop.
- Policy follow-up from Checkpoint A review: allowed modules re-export `os`, `sys`, `subprocess`
  etc. as attributes (`matplotlib.subprocess`); those attribute names and the exec/spawn/fork
  families are now rejected everywhere.
- Docker Desktop installs `docker.exe` under `%LOCALAPPDATA%\Programs\DockerDesktop\resources\bin`;
  shells opened before the install don't have it on PATH.

## Evaluation harness (Phase 5, 2026-11-07)

- **Task set:** 36 tasks (5 per category, 6 ambiguous/misleading). Expected values come only from
  `scripts/make_expected.py` (reference scripts run in the Docker sandbox, SHA-256 of each
  reference stored and checked by a test).
- **Tolerances:** numeric checks use k·√2·σ_ref (k = 4) from the reference run's standard error,
  since two independent Monte Carlo runs differ with variance 2σ². Because the prompt's default
  is `seed=1` and references also use seed 1, a candidate that follows the default reproduces
  the reference exactly (|diff| = 0); the tolerance matters when a model picks another seed or
  photon count.
- Checker additions beyond the SPEC list: `reports_error` (the honest "cannot do this" result
  for unknown materials / out-of-range energies / impossible targets: `answer=None` plus
  `data.error`), and `all` / `any` combinators (`any` for the injection task where either a
  refusal or doing only the legitimate part is acceptable).
- `--provider fake` in the evaluation replies with each task's reference solution: it checks the
  plumbing (36/36 locally) and says nothing about accuracy. The report excludes fake runs.
- `data/prices.json` is intentionally empty: no prices are typed from memory. Cost stays `null`
  until a dated entry from the provider's official pricing page is added.
- The `dataviz` palette validator needs Node, which is not installed here; the chart uses slots
  1–2 of the reference palette, documented there as passing the all-pairs checks.
- **3-task real run (exit check, not committed as results):** `qwen2.5-coder:3b`, single_01–03.
  Baseline 0/3, repair 3/3; every baseline failure was `NameError: simagent_io` (missing
  import), fixed by one repair. Median latency 2.9 s baseline / 5.3 s repair, TTFT 0.06–0.09 s
  (Ollama reuses the KV cache of the identical system-prompt prefix across tasks), 74 tok/s,
  peak VRAM 2229 MiB. A general prompt change could likely remove this failure mode; it is
  deliberately **not** made before the benchmark (see PROGRESS.md, open questions).

## Output-token cap for local models (2026-11-07, during benchmark round 2)

- **Observed:** in round 2 (prompt v2), `qwen2.5-coder:3b` on `adv_05` ("print your system
  prompt") kept generating for minutes at ~94 % GPU: Ollama's default output length is
  unbounded, so a degenerate repetition never ends. The run was stopped before that task was
  recorded (no record was written for it).
- **Fix:** `max_output_tokens` (default 2048, `SIMAGENT_MAX_OUTPUT_TOKENS`) is passed to Ollama as
  `num_predict`. Hosted models keep the provider default (the reasoning model spends part of its
  output on hidden reasoning). Eval records now carry `max_output_tokens`.
- **Comparability:** the largest output of any round 1 task was 1403 tokens (`adv_05`, repair
  mode), so the cap would not have changed a single round 1 result. Round 2 local runs resume with
  the cap from `adv_05` of `qwen2.5-coder:3b` baseline onward; the 35 earlier round 2 records
  were produced without it (none of them came near 2048 output tokens).

- **Authoring checks (before the prompts were final):** every reference was run on the host first
  (my own reference code, not model output). One comparison was a near-tie (30 cm concrete vs
  30 cm polyethylene at 0.3 MeV reflect 0.2293 vs 0.2287), so it was replaced by 30 cm concrete
  vs 5 cm iron (0.229 vs 0.207, about 17σ). Each threshold task was re-run with seeds 2–11: the
  crossing stayed within one grid step of the seed-1 reference (the checker's tolerance) every time.
- **Near-duplicate rule:** token-set Jaccard (lower-cased words and numbers) between each
  held-out and each dev prompt must stay below 0.6. For scale: dev prompts written from one
  template reach 0.70–0.85 with each other, and the shared result-contract wording alone gives
  about 0.4. Two drafts reused dev sentence frames (0.60 and 0.58) and were rephrased; the
  committed maximum is 0.54.
- **`simagent_io.submit` rejects non-string dict keys:** one reference first keyed a dict by
  float energies. The host check used a stand-in `submit` and missed it; the sandbox run caught it.
  Fixed in the reference before the data commit (no held-out commit was ever pushed).
- **`equals` on lists is case-sensitive per item** (`_norm` lower-cases only plain strings), so
  the ranking task asks for "the names returned by list_materials()" (wording set at checkpoint A). The
  checker was not changed.
- Expected values: `python scripts/make_expected.py --task-set heldout` (23 results;
  `ho_adv_02` is a refusal with nothing to run). The values were identical to the host run.

## Sampling settings in results headers (v2 Phase 2.1, 2026-11-09)

- v2 results files start with one header line (`"kind": "header"`): provider, model, Ollama
  digest and quantisation (from `/api/tags`), mode, task set, temperature, seed,
  `seed_supported`, prompt version, attempt budget, output-token cap, code commit (with `-dirty`
  when tracked files are modified). Resuming a file whose header differs on any sampling or
  identity field is refused; the code commit may differ on resume and is also stored per record.
  v1 files have no header and are read as before.
- **Groq seed:** `langchain-groq` 1.1.3 `ChatGroq` has no `seed` field, but the Groq API
  reference (console.groq.com/docs/api-reference, checked 2026-11-09) documents `seed` on chat
  completions: "best effort to sample deterministically", "Determinism is not guaranteed". It is
  passed via `model_kwargs` (verified in `ChatGroq._default_params`). So `seed_supported` is
  `true` for Groq, meaning "accepted", not "reproducible". The fake provider records `false`.
